# 技能规程（SKILL.md）编写规范

技能是员工的"岗位操作手册"：不进 system_prompt、不占上下文，播种进 Store 后由模型在命中触发条件时用 `read_file` 按需查阅。本篇讲怎么写一个合格的 SKILL.md。

机制原理见 [docs/articles/03](../articles/03-skills-sop-knowledge.md)。

## 技能 vs SOP：先选对载体

| | 技能（SKILL.md） | SOP |
|---|---|---|
| 适用 | 有多个分支判断的**规程**（怎么分析、怎么写报告） | **刚性流程**（必须逐步执行、不可跳步，如退款、升级上报） |
| 载体 | `backend/skills/<id>/SKILL.md` 文件 | seeds.py 里的内容字符串 |
| 触发 | 模型按触发条件自查规程 | 挂载说明进 system_prompt，语气更强 |
| 热改 | ✅ 编辑后运行时同步 Store | 改内容需重播种/资源中心 |

经验法则：流程允许模型自主裁量的用技能；每一步都不允许裁量的用 SOP。

## 文件结构模板

```markdown
---
name: market-daily-brief
description: 一句话能力描述，含"当用户……时使用"的触发语义。当 SKILL.md 正文
  缺少「## 触发条件」段时，系统兜底取这行作为触发说明。
---

# 技能名

一句话角色定位 + 本技能做什么。

## 触发条件

用户要……；或问"……"；或自动化值守任务触发（提示词带【自动化值守】标记）。
```

**两个会被系统程序化提取的位置，必须按格式写**：

1. **frontmatter `description:`**——编译期提取进技能摘要（注入 system_prompt 的那句话），决定模型"知不知道有这个技能"；
2. **正文 `## 触发条件` 段**——`compiler._extract_skill_triggers()` 优先提取这里（兜底才是 description），写具体的行为线索（用户会怎么问），不要写空话。

## 正文写法四条

**1. 步骤化，编号到可执行粒度。** 每一步 = 模型可独立执行的动作 + 用到的工具名。对比：

```markdown
❌ 分析竞品情况并输出结论
✅ 步骤 2：联网补最新动态
   1. 委派 intel-scouter 子代理检索该竞品近 30 天动态：新品/价格/渠道，至少 3 组关键词
   2. 可用 Playwright 连接器访问竞品官网核实；抓取失败退回搜索结果，不硬重试
```

**2. 把"红线"写成可判定规则。** 不写"要有信息素养"，写"每条外部信息必须标注来源与日期；缺失来源的条目不得进入看板"。

**3. 模板类产出直接内嵌完整模板。** 看板/报告类技能在正文放完整 HTML/结构模板（ fenced code block 包裹），并注明"只填数据、不改结构、无内容的区块写'本期无'"——参考 `market-daily-brief` 的看板模板。

**4. 输出通道约定要写死。** 需要产出 HTML 看板的技能必须写明：

- 用 `<!-- REPORT_HTML_START -->` / `<!-- REPORT_HTML_END -->` 独占行包裹完整 HTML，**作为消息文本输出**；
- 禁止 `write_file`/`execute` 落盘、禁止谎称"已保存到文件"——后端会把分隔符内 HTML 抽出来用 iframe 沙箱渲染，写盘用户反而看不到。

## 值守模式（无人值守场景）

如果技能会被自动化任务调用，加一节「值守模式」：

- 提示词带【自动化值守】标记 = 没有用户可交互：**不要反问澄清**，按默认范围直接执行；
- 数据源不可用时跳过并在产出中注明，不阻塞流程；
- 涉及外发的收尾动作必须走审批工具（如 `publish_briefing`），值守简报的收尾 = 提交发布审批。

## 全局共享与热改

- 技能目录是**全局池子**，多个员工可引用同一技能；改 SKILL.md 影响所有引用者，员工间差异化时复制目录换 id；
- SKILL.md 编辑后**运行时自动同步 Store**（内容变化才写），不需要重启——这是技能相对 persona 的最大工程优势；
- 但编译期缓存的技能摘要（description/触发条件）要重启才更新，所以**改 description 需要重启，改正文不用**。

## 自查清单

- [ ] frontmatter 有 `name` 和含触发语义的 `description`
- [ ] 正文有 `## 触发条件` 段，写的是用户行为线索而非空话
- [ ] 每个步骤点到具体工具名，参数要求可执行
- [ ] 红线是可判定规则（来源标注/禁止事项/失败退路）
- [ ] 模板类产出内嵌了完整模板与"无内容区块"兜底
- [ ] 会外发的内容写了审批工具调用时机
- [ ] `pytest tests/ -q` 通过（新增技能目录会被测试扫描登记）
