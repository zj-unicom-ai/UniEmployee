# 小察行业研究模块：全流程梳理与链接入库

梳理日期：2026-10-24。范围：研究采集、观察存储、分类去重、细分研判、主题综合、看板刷新、权限与失败恢复。当前实现按仓库既有的单实例服务运行方式设计。

## 结论

此前主要打通了“已有记录 → 数据看板”，采集与研判仍依赖对话中模型主动调用工具，无法保证“给一个链接 → 记录入库 → 研判更新”。现在增加由服务端控制步骤的链接流水线，模型负责内容提取和分析，不能自行决定是否跳过保存或任务状态。

## 发现的问题与处理

| 问题 | 影响 | 本次处理 |
|---|---|---|
| 对话回答完成不等于调用保存工具 | 用户以为已采集，平台却没有记录 | 独立 `/api/market-research/intake` 后台任务，完成条件必须包含观察、细分研判和主题研判 ID |
| 页面连接承担采集生命周期 | 关页面或断网后难以判断任务结果 | 任务状态持久化，页面只轮询；服务中断标记 interrupted，支持继续处理 |
| 相同 URL 可重复保存 | 虚增记录、来源数量和趋势热度 | 统一 URL 身份，去掉跟踪参数与锚点；兼容历史无 source_key 的记录；唯一索引约束新记录 |
| 来源入库和研判更新分离 | 新依据不会自动进入结论 | 顺序更新当前分类、其他有待吸收资料的分类、主题综合；全部保存才完成 |
| 更新失败只能重新研究 | 重复抓取、入库、生成版本 | 分阶段检查点，保留抓取正文和提取结果；研判生成键使重试可复用已保存版本 |
| 用 captured_at 判断一切更新 | 删除、恢复、改分类后旧结论仍可能显示 current | 校验有效引用，追踪分类/恢复修改时间，向主题传播 stale |
| 生成过程中资料发生变化 | 新报告可能用旧资料却显示最新 | 保存前校验资料范围签名；变化时失败并提示重试 |
| 阶段、价值等只存在 Markdown 中 | 依赖标题格式，自动采集后容易丢维度 | 新流水线保存 research_metadata 结构化字段；看板优先读取结构化数据，兼容旧正文标注 |
| 任意模型引用被静默过滤 | 生成内容与实际保存引用可能不一致 | 不在当前租户、分类、有效记录范围的引用直接拒绝保存；流水线另校验实际输入范围 |
| 普通写入接口未检查员工分配 | 可绕过模块访问边界写数据 | 与读取、采集接口统一检查登录上下文、租户和小察分配 |
| 单个 MCP 配置缺 transport / 初始化失败 | 正常连接器也可能全部丢失 | 补齐默认 stdio，逐连接器隔离失败；新链接流水线本身不依赖 MCP 工具成功启动 |
| 思考模型拒绝强制 tool_choice | 实际配置模型返回 400 | 使用 JSON Schema 提示 + 服务端 Pydantic 校验；无效 JSON 只修复一次，失败保留状态 |

## 现在的实际链路

1. 在研究工作台或专题看板顶部粘贴一个公开网页链接。主题取当前页面，细分领域默认自动判断，也可指定。
2. 接口保存任务并立即返回 202；后台按租户/主题串行，最多同时执行两条不同主题流水线，限制积压数量。
3. 抓取原文。限制 HTTP/HTTPS、大小、超时和重定向；每跳检查公网地址并固定连接 IP，TLS 仍校验原始主机名。去掉脚本等非正文内容。
4. 根据原文提取事实、逐字引述、摘要、分类、影响、不确定性和跟踪信号。逐字引述必须能在抓取正文里找到；不相关、无合法分类、正文不可读时不入库。
5. 统一去重后保存观察与结构化维度。重复链接复用已有记录；不会擅自恢复回收站内容。保留“原文披露”与“独立验证”的区别。
6. 基于该领域的平台观察生成细分研判，再综合已保存分类研判生成主题报告；新报告保留版本、来源和观察关联。其他分类有待处理依据时先补齐分类，避免跳过分类直接总结文章。
7. 人工修改分类、删除或恢复记录后，若主题仍有可用来源，会再次投递同一后处理队列。已无有效依据的分类保留历史版本，但退出当前主题综合的输入范围；全主题已无有效来源时保持待更新，不生成无依据结论。
8. 任务显示全部完成，页面刷新平台记录与研判。原文读取成功但研判失败时，明确显示“观察已入库，后续处理未完成”，重试从已完成的位置继续。

对话采集框中直接提交单个 URL 也进入同一后台链路。自由话题研究仍保留对话方式；一旦通过保存工具成功写入有来源的观察，同样投递后台后处理队列。定时来源、MCP 和对话保存共用该队列，后台调度器接续细分与主题研判；自由话题若没有保存任何观察，仍只能视为对话而非采集成功。

## 使用与排障

- 新任务：`POST /api/market-research/intake`，JSON 最少包含 `url`，`topic_id` 默认具身智能。
- 任务记录：`GET /api/market-research/intake`，普通用户查看自己的任务，管理员查看当前租户任务。
- 继续处理：`POST /api/market-research/intake/{job_id}/retry`。已完成任务不会重新执行；跨租户或无权操作的任务返回 404。
- 任务阶段：fetch → extract → save → category → topic → done；状态 queued / running / done / failed / interrupted。
- 记录已在回收站：先恢复，再继续处理。页面不会静默重新创建另一条。
- 模型错误：检查资源中心小察模型配置；已保存观察不会因为后续模型故障被回滚。
- 网页超时/403/空正文：提供可访问的文章原文；不会用搜索摘要冒充已读取原文。

## 明确保留的边界

- 自动读取当前支持公开 HTML 和文本网页。需要登录、验证码、强浏览器渲染的页面及 PDF/Office 附件不会伪装成功，需另接相应读取器。
- 存量数据存在明确的配图展示样例。当前“观察库条数”不能直接解释为有效行业事件数；应补充资料类型/证据等级并完成存量质量标注，避免样例、素材与研究成果混用。此次保留了原记录，没有擅自删除历史数据。
- URL 去重不等于事件去重。同一事件的转载、同一公告拆条和多个相似标题，仍需要跨来源事件聚合；记录数不能当作独立证据数或市场热度。
- 原文引述匹配只验证“来源确实这样说”，不自动证明来源内容属实。阶段、价值、优先级属于分析标注，需要人工反馈与后续证据纠正。
- 大样本研判输入有长度预算，分类正文保留实际输入条数/总条数。超出预算后应升级为分批合成或检索式证据选择；不能把资料截止时间误当作全库逐条阅读证明。
- 当前后台任务执行器是进程内单实例；进程中断能恢复状态，需点击继续处理。多副本部署前应换成数据库认领或外部任务队列，避免重复工作。
- 旧数据不自动补写模型等级，也不批量重写人工分类；有意避免一次梳理改动历史研究内容。
- 性能上仍有分类研判 N+1 读取与连接时建表自检；当前样本规模可运行，但应在数据量扩大前改为启动迁移和批量聚合。历史无链接索引记录的去重也有回退扫描。
- 用户验收/纠错、客户侧部署指标、事件聚合和自动跟踪信号回收仍是下一轮飞轮建设重点；本次首先打通提交链接到入库与研判的可恢复主链路。
