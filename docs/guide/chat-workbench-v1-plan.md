# 对话工作台 V1 设计稿与实施拆分

## 目标

把当前固定三栏、单行输入的对话页，调整为“对话为主、上下文与执行信息按需查看”的企业工作台。首版聚焦桌面端日常使用，同时保证平板和窄屏可操作。沿用现有 API、SSE、审批、Trace、附件和报告能力，先改善布局与交互。

## 交互原则

- 一屏只有一个主任务：阅读当前会话、撰写下一条消息。
- 历史会话和执行详情都可随时打开，但不长期占用聊天宽度。
- 员工身份始终清晰；模型选择和执行细节是次级控件。
- 进度说明用户可理解的动作和结果；原始工具细节放入“执行详情”。
- 长内容和文件是工作产物，不能被压成聊天气泡中的小卡片。

历史会话由左上角按钮打开为可收起侧栏；“执行详情”从右侧打开抽屉，显示阶段、工具调用、耗时、错误与审批状态。两个面板互不挤占默认聊天画布。标准模式将消息和输入区限制在约 1080px；全宽模式铺满可用画布。表格、代码和报告可使用完整内容区。

## 页面区域与现有组件映射

| 区域 | 当前实现 | V1 调整 |
|---|---|---|
| 顶栏 | `ChatView.vue` 内固定员工、模型选择、员工介绍和 Trace 按钮 | 员工身份/说明作为主入口；会话标题与菜单居中；执行详情作为次级入口；模型选择放入员工菜单或高级选项 |
| 历史 | `ConversationSidebar.vue` 永久占 240px | 改为可收起侧栏；增加当前员工筛选和关键词搜索（若列表 API 不支持服务端搜索，首版只筛当前已载入记录并标明范围） |
| 执行状态 | `PipelineSidebar.vue` 永久占 240px，展示固定步骤 | 改为右侧“执行详情”抽屉；默认只显示当前状态摘要，展开后看工具、阶段、耗时、错误和审批 |
| 消息 | `ChatMessage.vue` 展示气泡、Trace、审批、文件、评分 | 优化消息宽度和动作栏；统一引用、文件、报告等内容卡片；失败消息提供重试入口 |
| 输入 | `InputBar.vue` 使用单行 `n-input` 和附件按钮 | 多行自动增高输入；Enter 发送、Shift+Enter 换行；处理中将发送按钮换成停止按钮；保留文件队列并支持拖拽/粘贴 |
| 产物 | 文件卡片和 `ReportViewer` 嵌在消息内容流中 | 首版优化卡片尺寸与预览入口；后续再做可停靠的产物侧面板和版本切换 |

## 分期实施

### 当前进度（2026-09-23）

- V1.0 首轮已落地：聊天主区自适应、历史与执行详情抽屉、多行输入与 IME 安全发送、附件拖入/粘贴、停止生成、错误/中断状态和失败重试。
- 根据页面反馈增加宽度切换：标准模式下消息/输入区限宽并居中，全宽模式使用完整聊天画布；浏览器会记住上次选择。
- V1.1 会话管理已接入：标题/摘要服务端搜索、20 条分页加载、手动改名、置顶和归档；侧栏与独立历史页均可操作。手动标题受到保护，不会被后续 AI 标题覆盖。
- 消息复制和评价控件已改为键盘可操作按钮；普通回答复制保留原始 Markdown。
- 已修复窄屏应用主导航仍占满宽度的问题：768px 以下自动折叠为图标栏。
- 前端生产构建通过。真实浏览器端到端验收仍需连可用的开发后端检查附件、审批、停止和失败恢复路径；当前本机 8787 服务状态与本分支 API 不匹配，不能作为有效验收环境。
- 下一步：启动匹配当前代码的隔离开发环境，完成桌面/平板/手机操作验收；随后推进 V1.1 的回答版本管理、来源引用和审批卡信息架构。

### V1.0：布局与输入闭环

1. **布局重构**：历史侧栏默认收起，可打开、关闭；执行详情使用抽屉；聊天宽度自适应；窄屏切换为全屏抽屉/单栏。
2. **输入体验**：输入框自动增高并限制最大高度；Enter 发送、Shift+Enter 换行；处理中文输入法组合态，避免选字时误发送；保留草稿直到发送成功或由用户清空。
3. **流式控制**：发送期间提供“停止生成”；复用 `AbortController`；停止后将已有部分结果标记为“已停止”，与网络失败区分。
4. **失败恢复**：连接失败或服务错误时展示明确错误和重试按钮；重试沿用原问题、附件和员工/模型上下文。避免把审批等待误显示为失败。
5. **基础易用性**：附件移除按钮可键盘操作；常用控件有 tooltip、焦点态；新会话空状态给员工能力说明和 2–3 个真实、非演示数据的建议问题。

### V1.1：会话与回答管理

1. 会话列表支持搜索、重命名、置顶/归档和更多历史分页；先核对现有 conversations API，缺失操作再补端点。
2. 普通回答支持复制、重新生成、编辑原问题后重跑；采用新消息分支或新会话方式保存版本，避免覆盖已有审核记录。
3. 答案的知识来源使用可核验的引用卡：来源标题、章节/片段、更新时间、打开原文入口。若检索源不返回稳定引用数据，不展示伪造的“来源”链接。
4. 审批卡展示业务动作名称、目标系统、摘要参数、风险说明和审批结果；底层工具名/完整 JSON 收入展开详情。

### V1.2：产物工作区与企业协作

1. 报告、文档、SQL 结果可在右侧产物面板展开；对话和产物并排查看，支持下载、复制和继续修改。
2. 增加会话分享/协作前，先落实成员授权、文件 ACL、Trace 可见范围与撤权行为。
3. 结合真实用户需求增加快捷提示、模板任务、语音输入或 IM 入口；这些不阻塞桌面核心工作流。

## 组件和文件拆分建议

- `ChatView.vue`：保留页面状态编排；新增侧栏/抽屉状态，负责消息和上下文布局。
- `ConversationSidebar.vue`：加入收起状态、搜索框、加载更多和会话菜单。
- `PipelineSidebar.vue`：重命名/重构为 `ExecutionDrawer.vue`，展示当前运行状态和可展开步骤。
- `InputBar.vue`：拆出可复用的自动增高编辑器，处理键盘快捷键、IME 和附件粘贴。
- `useChatStream.js`：提供明确的 stop 状态与中断原因；网络错误、用户停止、审批暂停分别落状态。
- `ChatMessage.vue`：整理消息动作区；把来源、审批、报告/文件卡片按一种信息层级呈现。

首版先不动会话存储格式。重新生成/编辑消息、服务端会话搜索、项目级共享上下文属于 V1.1/V1.2，避免把 UI 改版和对话历史模型迁移绑在一个发布中。

## 验收标准

- 1440px 桌面宽度下，默认视图只显示聊天主区；侧栏打开后聊天仍保有可读宽度，执行详情不与历史栏同时挤压主区。
- 768px 及以下不出现横向滚动；历史与执行详情均可打开、关闭，打开面板后仍能返回输入焦点。
- Enter/Shift+Enter 对普通文本和中文输入法均符合预期；附件可添加、移除、拖入/粘贴；按钮状态与上传状态一致。
- 流式期间能停止；停止、审批暂停、上游报错和浏览器断网显示不同状态；已有回答内容不丢失。
- 失败重试不会丢失原消息/附件；不会意外创建重复审批或写操作。
- 键盘可完成员工选择、历史打开、输入、发送、停止和审批；按钮有可见焦点样式，动画尊重 `prefers-reduced-motion`。
- 建议问题只使用可验证的企业知识/工具能力；没有真实数据源时明确提示演示环境。

## 实施顺序建议

首个 PR：响应式双抽屉布局 + 多行输入 + 停止生成 + 区分中断/失败。

第二个 PR：重试 + 会话搜索/分页 + 消息动作栏。

第三个 PR：来源引用和审批卡信息架构（需要后端事件数据配合时再扩展 API）。

每个 PR 合并前用桌面、平板、窄屏各走一遍聊天、附件、停止、审批和断网恢复关键路径，并执行项目现有 CI。
