# 小察行业研判看板设计

## 设计目标

小察的主界面是行业研究工作台，不是聊天页，也不是资讯列表。用户沿着“主题 → 细分领域 → 研判依据”逐层观察：先在大主题看板理解行业全貌，再进入某个细分领域查看判断，最后沿来源回到支撑判断的资讯、论文、政策或产品进展。

```text
研究主题入口
  └─ 大主题看板：主题综合判断 + 细分领域入口 + 近期变化
       └─ 细分领域看板：分类趋势判断 + 驱动/风险/机会 + 跟踪信号
            └─ 研究依据：每条观察、原文来源、采集时间与分类
```

资讯是研判的证据层，不应占据主题首页的主要版面。每个判断都要能追溯到细分领域、具体观察和外部来源；没有可靠数据时明确显示覆盖不足，不用装饰性图表补空。

## 页面模板

### 1. 研究主题入口

入口只负责帮助用户选择要观察的大主题，并快速识别哪个主题近期有变化。主题卡片保持现有主题色，展示：

- 主题名称和一句说明。
- 已有细分领域研判数 / 总细分领域数。
- 有效研究依据数、最近更新时间。
- 是否有新证据待吸收、是否有分类研判待更新。
- 最近一次主题综合判断的一句话摘要；尚无报告时说明当前缺口。

不要在入口页展开资讯列表。点击主题卡片进入该主题自己的看板。

### 2. 大主题看板

大主题看板回答“这个主题整体发生了什么变化，判断由哪些细分领域支撑”。建议从上到下分为五个区域：

1. **主题判断**：主题名、最新判断摘要、报告版本、资料截止日期、可信度/证据覆盖状态，以及“更新主题研判”操作。没有主题报告时显示由哪些细分研判构成、还缺哪些分类，不显示虚构的总趋势。
2. **主题态势摘要**：最多 3–5 条有证据支撑的共同趋势、分化信号、跨领域影响。每条摘要标明支持它的细分领域和观察数，可直接跳至相关分类。
3. **细分领域入口**：以领域卡片或紧凑矩阵展示所有分类。每个入口显示分类结论、当前判断状态、依据数量、最新依据日期、新依据待吸收数。卡片信息重点是“这个领域目前怎么看”，而非单纯的文章计数。
4. **近期关键变化**：按时间呈现新增且重要的研究进展，以及它影响了哪个细分领域、是否触发了研判更新。条目提供来源质量和查看证据入口。
5. **证据覆盖与缺口**：显示已形成判断的细分领域、有效依据数、来源构成、更新时间分布和待分类/待复核量。覆盖率表达采集和研判完整度，不等同于市场份额或行业增长率。

大主题报告应由已有细分研判归纳而来。摘要需要显示它引用的分类，不允许直接跨过分类层，从资讯列表生成主题结论。

### 具身智能看板第一稿

具身智能主题采用专属的产业与技术研判布局，作为后续主题模板的探索稿：

1. **主题综合研判**：优先展示主题级报告；尚无主题报告时，明确显示细分研判覆盖数和证据边界。
2. **前沿技术雷达**：按 VLA 与具身推理、世界模型与空间智能、机器人学习与数据、灵巧操作与全身控制、仿真训练与工具链、评测/安全/Agent 融合六条技术主线积累观察，并展示各主线真实依据数。既有场景与产业分类保留，不重新解释旧记录。
3. **全球企业竞争**：展示建议关注名单与跟踪维度（技术能力、产品节奏、客户验证、交付规模、融资与生态）。名单只是监测框架，只有采集到带来源的企业观察后才显示最新事件或竞争判断。
4. **应用场景与商业成熟度**：呈现 L1 实验室验证、L2 真实场景试点、L3 付费部署、L4 规模化复制的统一尺标。案例缺少客户、运行时长、介入率和 ROI 等指标时不评级；对未公开指标标注“未披露”。
5. **产业链与市场动态**：提供能力底座、平台/核心部件、应用场景及商业化的分类依据入口。有效观察条数只能表示证据积累，不能替代市场规模、装机量或增长率。
6. **最新研究进展**：放在判断和分析框架之后，显示近期入库的观察、所属领域及来源数，作为回到证据层的入口。

页面视觉沿用铜色主题和当前工作台的浅灰蓝画布、深蓝文字。顶部增加锚点导航，方便在较长看板中切换。方案中的企业名单和成熟度级别属于监测框架，不代表数据库已有对应事件或已完成商业评级。

### 3. 细分领域研判看板

细分看板回答“这个小领域的趋势方向是什么，哪些事实支撑这个判断，下一步观察什么”。顶部提供面包屑“主题 / 细分领域”、领域标题、更新时间、资料截止日期、报告版本、可信度和新依据状态。

主体建议分成“判断”和“证据”两列：

- **核心判断**：一段可读的结论，以及趋势阶段/方向（仅在研判正文明确支持时出现）。
- **关键变化**：本期发生的变化及其与上一版的区别；有多期数据时才画趋势线。
- **驱动因素**：技术、成本、供给、需求、政策或商业模式等因素，每条附证据引用。
- **机会与风险**：分别列出潜在机会、约束和反向信号，区分事实与推断。
- **接下来跟踪**：未来要观察的指标/事件、为什么重要、当前数据是否可得。只有确有来源和时间序列时才显示具体数值。
- **证据覆盖**：本版引用数、领域累计有效观察、资料截止日期、来源类型、尚未吸收的新观察。
- **研究依据**：置于判断之后，支持按时间/来源/证据状态浏览观察。单条观察显示标题、摘要、归属领域、来源名称、发布日期/采集日期、来源等级和“本版已引用/待吸收”状态。
- **版本演进**：保留历次报告的结论、数据截止时间、引用数和变化摘要，便于确认新证据是否改变判断。

“研究依据”是可追溯的证据区，不重复做成首页主列表。用户可以从判断中的引用跳到指定观察详情，再查看原文来源。

## 两类看板线框

### 大主题

```text
小察 / 研究主题 / 具身智能                 更新主题研判
具身智能  ·  研究全景                           截止 2026-10-22
主题综合判断：……（版本、可信度、资料截止时间）

┌───────────────────────────┬────────────────┐
│ 主题信号与跨领域变化          │ 证据覆盖         │
│ 共同趋势 / 分化 / 影响         │ 分类覆盖、来源、缺口│
└───────────────────────────┴────────────────┘

细分领域
┌家庭服务机器人┐ ┌工业机器人┐ ┌商业服务机器人┐ ...
│当前判断       │ │当前判断   │ │等待积累依据   │
│依据/更新状态  │ │依据/待吸收│ │开始研究       │
└──────────────┘ └──────────┘ └───────────────┘

近期关键变化：时间线（变化 → 影响分类 → 查看证据）
```

### 细分领域

```text
小察 / 具身智能 / 工业机器人                更新研判  获取新依据
工业机器人   结论摘要                         Vn · 可信度 · 截止日期

┌───────────────────────────┬────────────────┐
│ 核心判断与趋势变化            │ 证据覆盖         │
│ 驱动因素 / 机会 / 风险         │ 引用/累计/待吸收   │
└───────────────────────────┴────────────────┘

后续跟踪信号（指标或事件；值必须可追溯）
本期研究依据（默认显示少量，支持查看全部与筛选）
版本演进（结论如何随新增证据变化）
```

两页都以左对齐为主。桌面采用宽内容区和不对称两列，主判断占据更大宽度，证据状态作为窄侧栏；移动端纵向排列并把细分领域入口放到判断摘要之后。

## 数据呈现规则

### 现在可以真实展示

现有数据可支撑主题/分类层级、报告结论与 Markdown 正文、报告版本、可信度、资料截止日期、有效观察计数、来源、更新时间、新增证据数量和研判新鲜度。第一版看板应优先使用这些字段。

### 需要后续结构化后再展示

市场规模、份额、增长率、渗透率、产品价格、成本曲线、企业排名和趋势折线都需要带口径、数值、单位、地区/样本范围、时间点和来源的数据。当前报告正文中的文字不能直接转换成精确图表，也不能仅凭资讯条数推断市场热度。

建议后续把研判结果逐步结构化为：

```text
summary / conclusion
key_signals[]       关键变化（判断、方向、证据引用）
drivers[]           驱动因素
opportunities[]     机会
risks[]             风险与反向信号
watchlist[]         待跟踪指标或事件
uncertainties[]     不确定性与证据缺口
evidence_refs[]     观察 ID、来源 URL、发布日期、事实/推断标记
```

时间序列指标单独存储并携带单位、统计口径、地域、时间和来源。信息不足时显示“尚无可比时间序列”，保留跟踪事项，不绘制占位曲线。

### 来源可信度与判断边界

证据条目显示来源类型和来源名称，例如官方统计/政策文件、论文/研究机构、企业公告、媒体报道、二次转载。来源级别先用于透明呈现和筛选，不自动把某类来源等同为真实。研判中明确标注：可核事实、来源方主张、分析推断、尚未验证；不确定性要与结论同时可见。

## 日常更新形成的“数据飞轮”

```text
定时任务或 Agent 注入新观察
  → 校验来源、去重并分类到细分领域
  → 新依据进入该领域证据区并标记“待吸收”
  → 更新细分研判，保存新版本与变化摘要
  → 汇总受影响的主题研判，保存主题版本
```

页面应明确反馈每一步状态：新记录已入库、分类待确认、领域判断待更新、主题判断待汇总。更新后显示“本次新增了什么、哪些结论变化、哪些仍未变化”。这样数据不断进来时，用户看到的是判断如何被证据推动，而不只是列表变长。

## 视觉方向

主题色沿用现有工作台：具身智能铜色（约 `#B45309`）、AI 前沿蓝色（约 `#2563EB`）、政策青绿色（约 `#0E7490`）。整体使用浅灰蓝画布（`#F6F8FB`）、白色内容面、深蓝墨色文字（`#16263D`）和中灰辅助文字（`#52657D`）。颜色只用于主题识别、状态和数据强调，不为每个模块额外增加彩色卡片。

正文默认字号不低于 16px；关键判断 18px，一级标题 30–36px，次级标题 20–24px，辅助信息不低于 13px。延续现有中文无衬线正文和清晰的深色标题，避免把关键状态写成小号英文标签。内容宽度控制在便于连续阅读的范围，较长报告采用自然段、短标题和证据引用，不把结论压进密集小字卡片。

## 设计复核

本设计把“判断及其证据链”作为视觉主轴，细分领域入口表示主题的研究结构，时间线说明新信息如何改变已有研判。它刻意不使用常见的装饰型 KPI 墙、无来源折线图和资讯卡片瀑布流，符合小察“通过证据积累来观察趋势”的主要用途，同时保留当前蓝/铜/青绿主题识别。

## 实施顺序建议

1. **已完成第一稿**：主题入口只负责选择主题；点击后进入独立的大主题看板路由。具身智能看板增加技术前沿、企业竞争、商业成熟度、产业链动态和研究依据模块；六条技术主线可独立积累观察，并与原有产业/场景分类并存；其它主题先使用通用模板。
2. 再调整细分研判页，突出核心结论、驱动/机会/风险、证据覆盖和后续跟踪；资讯放在判断之后。
3. 完善新增观察的分类确认、待吸收/待更新状态及主题/分类研判版本变化。
4. 数据量和口径稳定后，增加有来源的时间序列图表和细分领域横向比较。
