# 小网安全实操能力

同一个 net-ops 员工新增 security-practical 技能、沙箱 Python 工具和答案留存；
普通故障、指标、容量、SOP 分析仍使用原有能力。不需要新建员工或部署另一套产品。

## 更新后使用

启动时原有 backfill_netops_upgrade 会幂等补齐技能和工具指派，不覆盖自定义人设。
重新启动服务后，在小网技能选择中可选“安全实操”；普通用户的工具护栏仍然生效。
run_security_python 必须使用已配置的 OpenSandbox；未启用或不可用时明确失败，不在宿主机兜底。

每题新建一个会话，上传附件并输入：

> Q01，安全实操题。请先读取安全实操技能，分析附件，使用工具完成计算。
> 根据真实执行结果给出答案，用 save_security_answer 保存题号、结论和证据。
> 如遇工具或依赖故障请明确报告。任务完成前不要编造结论。

上传文件虚拟路径为 /data/<用户ID>/uploads/<会话ID>/...，Python 沙箱内为
/data/uploads/<会话ID>/...。脚本、完整工具返回及版本化答案保存在用户目录的
security-tasks/<会话ID>/；生成的其他提交文件也应写入此目录。

等待本轮结束，点击聊天顶部“导出实操记录”。ZIP 包含完整事件、附件、产物、
非敏感员工配置和文件 SHA-256；缺少结束事件的运行会在 manifest 中显式标记。
导出为内部格式，待官方格式公布后转换。源码与全程录屏必须另行准备并提交，
该 ZIP 不替代源码包或录屏。代码、记录和录屏至少保存三个工作日，不要清理原始记录。

选择“安全实操”技能或开启赛事模式后，完整记录独立于 2000 字符 Trace 预览，保存于应用数据目录 security-records/，
不受前端回放事件的定期清理影响。磁盘写入失败会中止求解；应提前检查空间及目录权限。

## 赛事运行配置（可选，同一应用）

在服务器环境或 .env 中配置，之后重启服务并新建题目会话：

```dotenv
NETOPS_COMPETITION_MODE=1
COMPETITION_MODEL=赛事模型名称
COMPETITION_BASE_URL=http://赛事接口地址/v1
COMPETITION_API_KEY=赛事提供的密钥
SANDBOX_ENABLED=1
```

还需按原部署文档配置 OpenSandbox 服务、镜像和用户数据挂载；开关本身不能安装这些依赖。
赛事配置仅作用于小网：只保留安全工具和时间工具，不加载企业知识库、连接器及显式子代理，
关闭自动模型标题。模型配置缺失即报错，不读取旧模型目录或回退其他接口。
现阶段适配 Chat Completions 工具调用；正式 API 的协议、工具调用和配额需现场确认。

新建赛事沙箱请求默认拒绝所有出网。必须在实际 OpenSandbox 部署上验证策略生效；
本轮不支持直接访问网络目标题。需要目标交互时，按官方授权范围另行开发并验证网络策略。
不要在已有开放网络沙箱的进程内热切赛事开关；须重启清理沙箱并验证新会话。
这个配置不是整台电脑或其他员工的网络隔离开关，比赛时只使用已验证的赛事小网会话。
依赖、工具和镜像提前安装；赛事期间不得在线下载或使用其他 AI 助手修代码。

## 赛前验收

完成一次附件→模型→工具→模型→答案→ZIP 导出，重启后可再次交互。
模拟超时、工具失败、大输出和中断，确认记录完整且错误可见；检查实际 API 请求只去赛事模型。
本地回归的模拟模型/沙箱测试不代表真实赛事模型与沙箱服务已验收，也不是实际解题正确率。
