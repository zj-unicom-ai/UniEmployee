# 演示话术速查卡（按数字员工绑定）

> **演示铁律：每段话术只发给【绑定员工】的对话窗口。** 平台有 6 个数字员工，同一个问题发给不同员工会得到完全不同的回答（各有各的知识库、技能和工具）——发错窗口演示就翻车。

## 一、员工与窗口对照（先认人，再说话）

| 数字员工（界面下拉框名称） | 岗位定位 | 在本演示中的角色 |
|---|---|---|
| **客户经理（解决方案顾问）**（xiaoxiao） | 全生命周期客户经营：签前方案 + 签后经营 | ★ **主角，场景 1-6 全部发给它** |
| 浙江联通售前客服（unicom-presale） | 浙江联通业务售前咨询（FAQ 知识库） | 不涉及——收到吉利话术它会用售前 FAQ 硬答，口径完全不对 |
| 数据分析专家（xiaoshu） | 定制型员工，专属分析工作台 `/app/analyst` | 不涉及——**它是定制型，普通聊天页的员工下拉框里根本不出现**，不要找 |
| 小经（biz-analyzer） | 经营分析与决策顾问（星云科技经营数据） | 不涉及——它的数据集是另一家公司的经营数据 |
| 小网（net-ops） | 算网运营专家（基站告警/工单） | 不涉及——它会往基站故障方向答 |
| 综合人力专员（hrbp） | HR 政策与员工事务 | 不涉及 |

**防混淆三条**：
1. 场景 1-5 在**同一个 xiaoxiao 会话**里按序演（上下文累积是特性：场景 3 的投诉工单会在场景 5 被自动关联，客户偏好在场景间被记住）；
2. 场景 6 用**两个全新会话**（A/B 各一个，中途要重启服务，避免旧上下文干扰对比）；
3. 除 xiaoxiao 外，不要把本卡任何话术发进其他员工窗口。

## 二、主角员工：客户经理（解决方案顾问）xiaoxiao

**进入方式**：聊天页顶部员工下拉框选「客户经理（解决方案顾问）」。

**针对该员工的演示前检查**：
- [ ] 已被分配给演示账号（admin 默认全量可用）
- [ ] 台账数据集为吉利版（`python scripts/generate_xiaoxiao_data.py`）
- [ ] 本体已播种（服务启动日志有 `seed_crm_demo_if_empty`）
- [ ] RAGFlow「客户档案」知识库含李总监/王工两份档案
- [ ] create_ticket 审批标记在位（服务启动自动 backfill）
- [ ] `npm install -g docx`（Word 生成依赖）

### 开场白

> 传统的数字员工演示大家见过很多——问答、写文档。今天这套客户经理数字员工有四个不一样：**数字全部来自真实系统检索与跑数、流程规程内化成技能、关键动作有人工审批闸门、背后还有一张业务本体关系图**。我们用浙江联通和吉利汽车的真实合作场景，从头走一遍它的一天。

### 场景 1｜拜访前客户 360 盘（客户经理 · 客户 360 画像）
**会话：xiaoxiao 会话①起点**

【念】
> 我下周要去拜访吉利汽车的李总监，帮我盘一下吉利汽车的情况和这次拜访的要点。

【看】知识库/本体/CRM 并用；先给一句话结论（"三线叠加的关键窗口"）；每节标来源；连"只要量化对比表、习惯约早 10 点"的偏好都带出来。
【价值】以前半小时的拜访准备，现在 30 秒，每条信息有出处。
【衔接】"这是'看'。盘点不能靠模型猜——接下来看它怎么'算'。"

### 场景 2｜合同商机优先级扫描（客户经理 · 续约与商机跟进）
**会话：xiaoxiao 会话①（延续）**

【念】
> 帮我扫一下目前手上所有客户的合同和商机，哪些需要优先跟进？

【看】execute 真实跑 pandas：741 万盘子、临期 362 万、停滞 348 万逐项吻合；"668 万集中在吉利一家"的集中度判断；P0-1 给"续约与二期 260 万打包上一次数字化委员会"的策略和逐字话术。
【价值】盘点从凭印象变成跑数据，风险排序拿走就能用。
【衔接】"扫出来最大的风险是吉利 320 万专网 23 天后到期。如果客户这时候来投诉呢？"

### 场景 3｜投诉处理审批闭环（客户经理 · 投诉受理与升级 · HITL）
**会话：xiaoxiao 会话①（延续）**

【念】
> 吉利汽车的王工投诉，说 5G 专网上周闪断了两次，产线 AGV 停了半小时，他非常生气要求赔偿，你来处理一下。

【看】识别红线 → 弹**人工审批卡**（自动关联 320 万合同）→ 点批准 → 工单落号 T0912102010；回答中的关键句："**在拿到证据前不会向王工认责、更不会承诺赔偿**"，并主动核查告警数据时间覆盖。
【价值】AI 冲在一线，风险闸门在人手里；没证据不编、不承诺。
【衔接】"投诉处理完了，生意还要往前走——极氪二期的方案该出了。"

### 场景 4｜二期方案 Word 生成（客户经理 · 签前方案能力）
**会话：xiaoxiao 会话①（延续）**

【念】
> 帮我准备极氪工厂 5G 专网二期的方案材料，生成 Word 文档。

【看】读技能规程 → 检索 → 生成 Word → 回答下方出现**文件卡片，当场点下载**；它自己声明"报价是占位、这份文档还不能直接发客户"。
【价值】一句话出标准初稿；半成品不会伪装成成品。
【衔接】"方案发了，人也要去见。拜访回来信息怎么沉淀？"

### 场景 5｜口述拜访纪要（客户经理 · 纪要与客情记忆 · 第二张审批卡）
**会话：xiaoxiao 会话①（延续）**

【念】
> 刚从吉利回来，口述一下拜访纪要：今天上午十点见了李总监和王工。聊了三件事：一是 5G 专网一期续约，李总监说集团预算 9 月底前能批下来；二是极氪二期，他们希望方案里增加边缘算力节点做视觉质检本地回传；三是王工要求把 AGV 的 QoS 优化提前到 9 月 20 号前完成。你整理一下。

【看】口述变结构化纪要落档；"9 月 20 号前完成"被识别成交付承诺 → **第二张审批卡**（自动关联场景 3 的投诉工单 T0912102010）；偏好写入长期记忆。
【价值】口述即沉淀，承诺逐条被追踪，人走单不丢。
【衔接】"最后是今天最想给大家看的——这些能力的底下，有一张业务本体关系图。"

### 场景 6｜本体价值 A/B（客户经理 · 业务本体 · 压轴）
**会话：xiaoxiao 全新会话②（B 组）与全新会话③（A 组）；中途重启服务**

**操作**：资源中心摘掉 xiaoxiao 的 `ontology_find_entities` / `ontology_query_relations` → **重启服务** → 会话②念话术（B 组）；恢复工具 → **再重启** → 会话③同样话术（A 组）。

【念（两组一字不差）】
> 通过业务本体查一下：极氪工厂 5G 专网二期对应我们哪份现有合同？涉及哪些产品？技术侧对接人是谁？

【看 B 组（没本体）】反复 grep 台账、翻知识库，靠"一期/二期"字样推断，自己承认"台账无法回答，需向李总监确认"、"台账未标注两者为同一站点"。能用，但每步不可验证。
【看 A 组（有本体）】8 组关系查询，直接给出关系路径：`极氪二期(93) --correspond_to--> HT-2025-0031(87) --include--> 5G 专网(96)`；权威结论"**二期不是新建专网，是对一期的扩容**"——这个事实台账和知识库里都没有，只在这条关系边上；还主动暴露"边缘算力节点本体未建模"。
【价值三连】推断变查证（可解释可审计）→ 一次建模处处受益 → 缺口显性化倒逼数据治理。

## 三、其他员工怎么应对观众提问（不演示，但要能接住话）

| 观众可能问 | 一句话应答 |
|---|---|
| "售前客服（小联）能干嘛？" | 浙江联通业务售前咨询，绑定「浙江联通业务知识库」——现在这套客户经理演示讲的就是签后经营，小联管签前咨询，两边正好互补 |
| "数据分析专家（小数）呢？" | 定制型员工，有专属分析工作台 `/app/analyst`，走 SQL 问数和报表，不在普通聊天下拉框里——需要的话可以单独安排一场 |
| "小经/小网/人力专员呢？" | 分别是经营分析决策、算网运维（基站告警/工单/SOP）、HR 事务——同一套平台，换一套知识库、技能和工具就是另一个岗位的员工，这正是"编排"的意义 |

## 四、收尾话术

> 回顾这位客户经理的六步：**真实数据**（客户 360、扫描）、**流程规程**（方案、纪要）、**权限内控**（两张审批卡）、**关系资产**（本体 A/B）。所以它不是一个聊天机器人——它是带着数据库、知识库、流程和红线上岗的客户经理。人负责关系和判断，它负责记得住、查得准、不越权。而且刚才所有能力都不是写死的代码——知识库、技能、工具、本体，全部是页面化编排出来的；换一套配置，它就是售前客服、HR 或算网运维。

## 五、应急预案

| 状况 | 处置 |
|---|---|
| 话术发错了员工窗口 | 立即回到 xiaoxiao 会话重发；发错会话不影响正确会话（会话相互隔离） |
| A 组没调本体工具（场景 6） | 确认重启过服务（agent 编译缓存不热更新）；话术保留"通过业务本体查"字样；再不行新会话重问 |
| 生成文件没出现下载卡片 | 浏览器强刷加载新版前端；确认服务为重启后的进程 |
| 审批卡没弹 | 确认服务重启过（自动补 create_ticket 审批标记）；用 admin 账号 |
| 数字对不上 | 确认跑过 `scripts/generate_xiaoxiao_data.py`（吉利版台账）；日期口径以 `get_current_time` 为准 |
| 本体查询"未找到" | 确认启动日志执行过 `seed_crm_demo_if_empty`（吉利实体播种） |
